# OpenFX Research Lab — Project Identity and Naming Decision

**Decision date:** 2026-10-29  
**Status:** Adopted for project communication and repository documentation; GitHub repository slug rename still pending in repository settings.

## Names

- **Formal name:** OpenFX Research Lab
- **Short invocation name:** OpenFX
- **Proposed repository slug:** `openfx-research-lab`
- **Tagline:** Research. Test. Validate. Improve.
- **One-line description:** AI-assisted open research, development, backtesting, and independent validation of Forex trading strategies.

## Why this name

The earlier name `video-research-team` overemphasized source/video collection. The project's charter identifies strategy research, implementation, systematic backtesting/optimization, and independent validation as the primary workstream. Source discovery and extraction are supporting capabilities. “OpenFX Research Lab” reflects the wider mission and is understandable to potential contributors in algorithmic trading, MQL5, Python, data engineering, and quantitative research.

“Open” expresses an intention to welcome collaboration; it does not mean that every strategy, credential, dataset, or operational control should be public. Sensitive strategy details and execution credentials must remain protected.

## Scope and integrity

The project seeks reproducible evidence, not guaranteed profits. Every result must preserve its code/data/configuration identity and relevant logs. Negative results must remain available. No test, compile, deployment, or strategy edge may be claimed without evidence.

## Repository rename status

The repository currently remains `karimsatlikh-collab/video-research-team`. The connected GitHub tools available for this work support reading and changing repository files, but do not expose the repository-administration rename action. Therefore the README and contributor documentation can adopt the new identity now, but the repository slug and GitHub's repository description must still be changed by an owner in GitHub settings.

**Do not create a second repository merely to simulate a rename.** Preserve existing history, issues, commits, and references by renaming the current repository in its settings when possible. After the rename, verify the redirect and update any hard-coded repository-name references as needed.
